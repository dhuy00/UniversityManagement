### API transaction contract

1. Authenticated request arrives with JWT containing `app_user_id` claim
2. Middleware intercepts and checks for `app_user_id` claim
3. If present: open connection → begin transaction → set security context
4. Repository commands use the same connection/transaction
5. On success: commit transaction
6. On failure: transaction rolled back by disposal

**Critical**: Never accept user ID from client input. Always use the
server-validated claim from the authenticated principal.
